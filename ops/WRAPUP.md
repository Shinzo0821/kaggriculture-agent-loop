# 朝の締めセッション指示書（overnight.sh がループ終了後に1回だけ渡すプロンプト）

あなたはこのリポジトリの Supervisor。今夜の実験サイクルは全て終了している。実装・評価・提出は**しない**。
やることは日次レポートの仕上げだけ。10ターン以内で終えること。

1. `state/HANDOFF.md` と `state/STATUS.md` の「次の一手」、今夜のサイクルログ `state/overnight_logs/<今日のYYYYMMDD>_cycle*.log` を読む
   （`.log` は各サイクルの要約テキスト。`.log.json` / `.stderr` は読まなくてよい）。
   評価ジョブのログ `*_eval.log` と回収ログ `*_collect.log` も、失敗があれば見る。
2. `.venv/bin/python ops/daily_report.py` を実行（UTC 日付で `state/reports/YYYY-MM-DD.md` が生成される。既に存在すれば上書きされるので先に実行すること）。
   レポート先頭は「採用判断シート」（順位・相関 n・**承認待ち**・目標曲線との差）と「運用上の問題」。
   **承認待ちがあるか、キャリブレーション警告が出ているか、運用上の問題があれば、所感の1行目に書く**
   （通知は入れない方針なので、人はここしか見ない）。
3. レポート末尾「## 所感・次の仮説」に 3〜5 行追記: 今夜の成果（王者交代/提出）、閉じた系統、次の仮説、運用上の問題（サイクルが途中で止まった・上限に当たった等があれば必ず書く）。
4. `state/HANDOFF.md` を今夜の結論に合わせて更新する（**100 行以内**。溢れたら「今夜の詳細」から
   STATUS へ移す。**行数を削るために王者・次の一手・承認待ち・人への質問を落とさない**。王者・数字・次の一手・
   未完了作業・承認待ち・人への質問）。STATUS.md の「次の一手」が食い違っていれば、その1節だけ整合させる
   （大きな書き換えはしない。経緯は STATUS、要約は HANDOFF）。
5. **3 夜ごと**（前回の retro から 3 夜経っていれば）`state/retro/YYYY-MM-DD.md` を
   `state/retro/TEMPLATE.md` の 5 点だけ書く。
6. `git add state/reports state/STATUS.md state/HANDOFF.md state/retro` → コミット（メッセージ例: `report: YYYY-MM-DD (所感付き)`）。`git add -A` 禁止。

制約: 個人ディレクトリ `../personal` へのアクセス禁止。提出禁止。時刻待ち禁止。
