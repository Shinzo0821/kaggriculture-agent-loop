## 0. 要旨（結論先出し）

**YARN_STORE が 2 軒以上引かれた町（seed の約 12%）でだけ、d12-16 に SE($4,000) を買い、
羊を 4→8 に段階増頭し、SE に飼料小麦 6 枚を足す。y≤1 の町では一切何もしない（親と
バイト単位で同一挙動）。** y=1 での増頭と、削って作る資金調達（メロン第2波カット・牛→羊
スワップ）は数字で棄却（§3）。期待効果は発火 seed で対マージン +$3k〜+$9k、非発火 seed で
厳密に 0（この「0」が対応付き評価の検出力を担保する。§8）。

## 1. エンジン算数（全て engine 実測値から。発明なし）

### 1a. 町抽選のタイミングと確率

- 抽選は `_end_of_day`（kaggriculture.py:884-891）で `next_day % 3 == 0` の時 1 軒、
  一様・**復元抽出**（8 店種、p(YARN_STORE)=1/8）、総数 8 軒で打ち止め。
  → **d3,6,9,12,15,18,21,24 の朝に 1 軒ずつ増える。d 日の朝に見えている軒数 = floor(d/3) 回分**。
- P(y≥2)（YARN_STORE 2 軒以上）: d12 朝(4回)で 7.9% ／ **d15 朝(5回)で 12.1%** ／
  d18 朝(6回)で 16.6% ／ 最終(8回)で 26.4%。P(y≥1) 最終 65.6%、E[y]=1.0。
- **注意（Implementer/Evaluator 必読）**: 抽選 rng は同じ `_end_of_day` 内で**雑草スポーンの後**に
  呼ばれ、雑草の rng 消費回数は両農場の空きタイル数に依存する（kaggriculture.py:836-840,877,891）。
  つまり**抽選列は seed だけでは決まらず、d12 までの盤面（＝方策）に依存する**。ただし本設計の
  発火は d12 以降で、d12 までの挙動は親と同一なので、**発火判定日までの抽選は親と候補で必ず一致する**。
  発火後の d15-24 の抽選は分岐しうる（§8 の対応付き評価の注記）。

### 1b. 羊毛の需給（y 別）

- 町消費 = 1（町中心）+ 12×y ／日（単品店 multiplier 2、4step 毎 = 6 回/日 ×2）。
- 供給: 毎日 CARE すると羊 1 頭 = 3 日毎に 1+3(バンク) = **4 個/3日 ≈ 1.33 個/日**
  （README「Animal Care」。gen0031 実測 136 個/季 ≒ 4 頭 ×1.13/日と整合）。
  自分 4 頭 ≈ 5.3/日、強帯の相手 4-6 頭 ≈ 5.3-8/日、**両者合計 ≈ 10.6-13.3/日**。
- 需給差:
  - **y=0**: 需要 1/日。既存 8 頭分ですら +59 個（floor 到達点、sq: 640×(x/105)²）を
    突き抜ける。追加羊毛は売れない（β/床で止まる → terminal 全損）。
  - **y=1**: 需要 13/日 ≈ 供給。ほぼ均衡（seed7 実測: 最終在庫 +10、価格 $194）。
    追加供給の限界価格は最初の +20 個で −$23、+44 個で −$112 と逓減。
  - **y≥2**: 需要 25+/日。均衡供給のまま **12+/日の純ドレイン** → d20 頃に在庫 −100 超 →
    価格は上限帯 **$237-240**（below=log は T=105 で $240 到達）に張り付く。
    こちらが +5.3/日足しても在庫は I0 未満のまま＝**自己値崩れゼロ**。

## 2. 正直な ROI（設問 1 の回答）

前提: 発火 = y≥2 を d12-16 に観測。SE を d12-13 に購入、羊 +4 を d13/d14 に 2 頭ずつ設置。
追加羊毛 ≈ 68-72 個、CARE 取りこぼし 10% を引いて **64 個**。

| 項目 | ベース（$230・d29 分込み） | ストレス（$200・d29 分落とし・労働満額） |
| --- | --- | --- |
| 羊毛収入 | 64 × $230 = **+$14,700** | 56 × $200 = +$11,200 |
| 羊 4 頭 | −$2,000 | −$2,000 |
| SE 土地 | −$4,000 | −$4,000 |
| 飼料 +4/日 ×16日 | −$2,700（自給小麦の機会費用 $41-45/個） | −$2,700 |
| 労働（FEED/CARE/HARVEST/建設 ≈165h × $18/h 上限値） | −$2,000（hands に空きがある実態を割引） | −$2,970 |
| 肥料副産物 64 個 | +$640（肥料は glut、$10/個で計上） | +$640 |
| **羊毛プログラム小計** | **+$4,640** | **+$170 ≈ 0** |
| SE 小麦（計画 6 枚＋fallback ~11 枚 × 2-3 回転 × +$64/回転） | +$2,000〜2,700 | +$1,000 |
| **発火 seed 合計（対自分資金）** | **+$6,600〜7,300** | **+$1,200** |

- 対マージンはさらに denial が乗る: y≥2 では相手も羊毛を高値で売っており、こちらの供給が
  在庫を押し上げる分だけ相手の希少プレミアムを削る（相手 −$600〜1,200）。**マージン期待 +$3k〜+$9k**。
- **SE 単独（羊毛抜き）は負** — scout 実測どおり（Rayk 3 実装族 ×450 戦全敗、
  `knowledge/scout/2026-09-04_public-knowledge.md` §13）。SE が浮くのは「上限価格に張り付いた
  品目の増産枠」としてだけ。だから **y≥2 限定**。SE 小麦 +$1-2.7k は $4,000 を単独では返せない。
- **y=1 で +2 頭（SE 経由）も負〜ゼロ**: 限界価格 ≈$175 に逓減、36 個 ×$175 − 羊$1,000 −
  飼料$1,350 − 労働$1,500 + 肥料$300 ≈ +$2,750。SE $4,000 を引くと **−$1,250**（SE 小麦を
  足しても ±0）。→ **y=1 は現状維持（4 頭）が正解**。

## 3. 資金調達の選択肢（設問 2 の回答）— 推奨: (a) SE 購入・y≥2 限定

- **(a) SE $4,000 を買って何も削らない**（採用）: 上表。SE は羊毛専用ではなく、飼料小麦 6 枚
  （unfed 対策の主役、§5）と fallback 小麦 ~11 枚が $4,000 の 3-7 割を回収する。パスチャは
  シェッド南東角（(5,5) がシェッド操作タイル）の隣接に置くので通勤コストはほぼゼロ
  （scout の「SE は通勤で死ぬ」への反論はこの配置が根拠）。
- **(b) 牛→羊スワップ（牛 8→6、羊 4→6）**（棄却）: パスチャ増設不要で $0 だが、gen0037 で
  **牛削減は用量反応つきで棄却済み**（マージン −$8,158 [−10,167, −6,149]）。牛乳は linear
  above（傾き $2.1/個）なので牛 2 頭分 ≈62 個を市場から引くと相手の後半牛乳が最大 +$130/個
  戻る。牛は生産資産ではなく denial 装置（EXP0037 学び 1）。再試行しない。
- **(c) メロン第 2 波 2-4 枚をパスチャ化**（棄却）: メロン 2 波タイルの粗利 ≈$500/枚に対し
  羊 1 頭 +$2,000 前後で一見勝つが、メロン above=sq の傾き（+132 近傍で $2.64/個）×
  引き上げ 12-24 個 × 相手の後半メロン ≈40 個 → **相手へ +$1,300-2,500 の贈り物**。
  gen0035/0037/0040 と同じ失敗形。y=1 のための調達としては差引ゼロ以下。

## 4. 町条件付き頭数（設問 3 の回答）

トリガは**ステートレス**に毎ターン導出する（エージェントは純関数のまま）:

```python
YARN_MIN = 2          # y>=2 でだけ拡張（§1b: y<=1 は増頭の限界収入が負〜ゼロ）
EXPAND_W0, EXPAND_W1 = 12, 16   # SE 購入トリガ窓（d18 発火は SE 込みで損益ゼロ、§1c）
COW_MAX = 8           # 既存 cow_target の上限。触らない

def yarn_count(shops):
    return shops.count("YARN_STORE")

def expansion_active(day, yarn, unlocked):
    # SE を買った事実そのものが永続フラグ（unlocked_quadrants は減らない・
    # yarn_count は単調増加なので、この式はステートレスでも一貫する）
    se_owned = len(unlocked) >= 4
    return yarn >= YARN_MIN and (se_owned or EXPAND_W0 <= day <= EXPAND_W1)

def sheep_target(day, yarn, se_owned):
    if yarn < YARN_MIN or not se_owned:
        return 4                 # y=0/1: 現状維持。過剰供給に踏み込まない
    return 8                     # y>=2 かつ SE 取得後。設置は空きパスチャ数で自然に位相化
```

- **y=0**: 4 頭のまま（既存分は denial として残す。減らすのは gen0037 の失敗形）。
- **y=1**: 4 頭のまま（§2 の負の ROI）。
- **y≥2（d12-16 に観測）**: `land_target` が 4 を返して SE 購入 → 翌日 SE パスチャ 4 枚建設 →
  羊を **空き建設済みパスチャ数まで**購入（自然に 2+2 の 2 日位相になる）→ 8 頭。
- y≥2 が d17 以降に初観測された場合は**何もしない**（窓が閉じている。§1c の d18 行）。

## 5. 飼料ランプ — unfed_days=0 の機械的保証（設問 4 の回答）

EXP0040 の unfed 3 日の構造: 需要 12→16/日に対し小麦計画 20 枚 ≈16/日で**余剰ゼロ**化＋
新設置日の個体への在庫切れ。既存の防御（PICKUP h14 まで・PLACE h18 まで、緊急 FEED pri 0、
h12+ の越境救済）は残っているので、**足りないのは在庫の先回りだけ**。3 点で塞ぐ:

1. **先行バッファ購入（発火日 T、羊より先）**: 飼料の市場購入判定（gen0044 L1181-1188）の
   `owned_total` を `planned_total = owned_total + max(0, sheep_target(...) - owned["SHEEP"])`
   に置換。T 日の時点で在庫目標が 24→32 になり、羊が居ない **T 日から** 12 個/ターンの
   買い足しが始まる。飼料は $45/個 ×8 = $360、羊 1 頭の産出 $3,000+ に対して誤差。
2. **売却リーク防止**: `feed_buffer = total_placed * 3 + 2`（L1110）も `planned_total` 基準に
   置換。トリガ日に余剰小麦を売ってしまってから羊が来る、を防ぐ。
3. **恒常供給の増設**: `CROP_PLANS["WHEAT"]["tiles"]` に SE の 6 枚を `from_day 12` で追加
   （§6 の座標）。d(T+1) 植付 → **d(T+5) から +5/日** ≈ 需要増 +4/日を恒常カバー。
   T+1〜T+4 のギャップは (1) のバッファ 8-12 個＋既存余剰 ~4/日で埋まる（需要増は
   T+2 の 2 頭目設置までは +2/日）。

タイムライン（T = トリガ日、12≤T≤16）:

| 日 | 行動 | 飼料収支（需要/供給+在庫） |
| --- | --- | --- |
| T | BUY_LAND(SE)、飼料先行購入開始、小麦売却リーク停止 | 12/16+バッファ↑ |
| T+1 | SE パスチャ 4 枚建設（朝、pri 2.6）＋ SE 小麦 6 枚植付＋羊 2 頭購入→PLACE→当日 FEED | 14/16+8 |
| T+2 | 羊 2 頭購入→PLACE→当日 FEED | 16/16+8 |
| T+3〜T+4 | 市場買い足しで在庫維持（planned_total 基準で自動） | 16/16+バッファ |
| T+5〜 | SE 小麦の初収穫 | 16/**21** |

**合格ライン**: 発火 seed のスモークで `micro_audit --assert` の unfed_days=0 / uncared_days=0 /
noop_total=0 を通してから評価に回す（CLAUDE.md 絶対ルール。gen0040 の再発防止）。

## 8. 評価計画と未解決リスク

  **事前計算ではなく親の replay から読む**）＋非発火 seed 1 本。`micro_audit --assert` で
