### 3-1. 変更する関数と規則（定数の値ではなく規則の形）

対象は `_agent` の植付スケジューラ（gen0062: 839-865 行）と `eval_todos` の層決定（1435-1441 行）。
新しい定数は持ち込まない。`window_end[crop]`（既に 3-D 種購入が使っている「今開いている窓の最終日」）と
`LOSS_PRIS` / `VISIT_LAYER` の既存概念だけを使う。

```
# 植付スケジューラ（todo 生成側）— 変更前
todos.append((plan["plant_pri"], x, y, ["PLANT", crop], "SEED:" + crop))
# 変更後: 締切フラグを need に持たせる（claimed の同定は pri のままなので他の会計は不変）
deadline = (day == window_end[crop]) and crop != FALLBACK_CROP   # 窓が今日閉じる計画作物だけ
todos.append((plan["plant_pri"], x, y, ["PLANT", crop], ("SEED!" if deadline else "SEED:") + crop))

# eval_todos（層決定）— 変更前
lay = pri_layer(eff)
if visit_ok and d == 0 and op[0] in DAILY_TILE_OPS: lay = min(lay, VISIT_LAYER)
# 変更後: 締切 PLANT は「今日やらないと資産（種＋タイル日）が失われる仕事」として
#         VISIT_LAYER と同じ持ち上げを受ける（距離条件は無し。crit は 2 のまま＝LOSS_PRIS より下）
if need.startswith("SEED!") and day < FINAL_DAY: lay = min(lay, VISIT_LAYER)
```

`_rank`（gen0060 系のバックログ巡回）にも同じ持ち上げを入れる（入れないと「所有者の順位付けの再現」が嘘になる。
FIX0033 と同型）。`planned_seed` / `plant_slots` / 3-D の種購入は `need[5:]` で crop を引いているので
接頭辞の長さを変えない（`SEED!`/`SEED:` とも 5 文字）。

- **親の分岐**: gen0062 が `gate.pass` → 親 gen0062（`_rank(it, px, py, is_farmer)` に持ち上げを足す）。

  gen0060 では 6 枚が d12 に間に合わず、その日に持ち上げれば植わる見込み）。
