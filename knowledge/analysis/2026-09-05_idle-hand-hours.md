# 2026-09-05 待機しているユニット時間 — gen0026 が捨てた 1,371 時間

## きっかけ

gen0027（SW 解禁）が強帯で検出不能に終わったので、上位実装との差がどこにあるかを
**同一試合・同一の物差し**で測り直した（`harness/micro_audit.py --both` と、
リプレイから行動種別を数える）。相手は kaito_v48（この試合 $99.5k、こちら $60.8k）。

## 事実 1: 行動の内訳が 1.5 倍違う

vs kaito_v48 s42、gen0026 の 1 試合ぶん（両者の全ユニット・全時間）:

| 行動 | gen0026 | kaito_v48 |
| --- | --- | --- |
| WATER | 724 | 978 |
| HARVEST | 223 | **420** |
| FEED / CARE | 276 / 276 | 347 / 342 |
| PLANT | 119 | 203 |
| FERTILIZE | 19 | **80** |
| SELL | 133 | **571** |
| **実作業 合計** | **2,172** | **3,253** |
| **PASS（明示的な待機）** | **1,680** | **379** |

hands の数はほぼ同じ（micro_audit の hands は 10 vs 9、HIRE は 298 vs 282）。
**同じ人数で 1.5 倍の仕事をしている。**

## 事実 2: 待機は gen0026 が作った

同じ相手・同じシードで自系統を並べる:

| 世代 | PASS | WORK | 変更点 |
| --- | --- | --- | --- |
| gen0022 | 702 | 1,977 | ゾーン固定（row-major） |
| gen0025 | **309** | 2,184 | 肥料 |
| **gen0026** | **1,680** | 2,172 | **ゾーン空間化＋越境 claim 禁止** |
| kaito_v48 | 379 | 3,251 | — |

**gen0026 は PASS を 309 → 1,680（5.4 倍）に増やしたのに WORK は増えていない。**
1,371 ユニット時間（現行 WORK の 63% に相当）を丸ごと捨てている。
それでも gen0026 が親比 +$14k 勝ったのは、層ごとの巡回と出荷制御の効きが
それを上回ったから。**捨てている capacity は手つかずで残っている。**

## 原因

gen0026 の変更 2（越境 claim の禁止）。global fallback は `_owner_can_come` が False の
仕事しか拾わない。判定は `所有者の歩く距離 + 1 <= 24 - hour` なので、**日中はほぼ常に
「所有者が来られる」**になる。自ゾーンの仕事が尽きた hand は他ゾーンを手伝わずに待機する。

gen0026-2 が塞いだ穴（所有者がそこへ歩いている最中に横取りされる）は本物だが、
**禁止が広すぎた**。「所有者が来られる」と「所有者が来た方が早い」は違う。

日別に見ると待機は 2 か所に固まる:

- **序盤 d0-9**: PASS 535 / WORK 427（相手は 166 / 550）。タイルも動物も少ないのに
  hands は既に 10-13 人いる。
- **終盤 d26-29**: PASS 389 / WORK 275（相手は 54 / 553）。清算期に仕事が尽きる。
- 中盤（d10-25）は WORK が **90-98/日で頭打ち**。相手は 130-180/日まで伸びる。

## 検証（gen0028A: 「所有者より厳密に近ければ拾ってよい」）

`_owner_can_come` に「呼び出し元の方が所有者より近いなら False」を足した。
この分岐は自ゾーンに仕事が無い hand しか通らないので、拾っても自ゾーンは痩せない。

vs kaito s42: PASS 1,680 → **1,477**（−12%）／ WORK 2,172 → **2,303**（+6%）／
タイル利用率 77.4% → **80.4%**（自系統の最高）／ 生産タイル日 987 → 1,045。
**ただしスモーク 3 シードとも最終資金が下がった**（$56.9k→$52.9k、$62.5k→$42.1k、
$67.7k→$57.8k）。3 歩以上 15.7%→16.6%、hop 0.972→1.091 と移動が増えており、
**拾った仕事の価値が歩いた時間を上回っていない**疑いがある。
→ 距離上限つきの B 版（`CROSS_ZONE_MAX_DIST = 2`）と 24 シードで A/B する。
（スモークの資金は判定に使わない。`2026-09-05_seed-detection-limit.md`）

## 副産物: 見つかった別の穴（未修正）

シェッドの一括 PICKUP 2 か所（小麦・肥料）の key が **層空間になっていない**。
gen0026-4 で `eval_todos` の key を `(pri, 距離)` から `(層, 距離, pri)` に変えたとき、
この 2 か所だけ `(pri, 距離)` のまま残った。float の pri が層番号（int）と比較されるので、
肥料 PICKUP の 2.87 は「層 2 と層 3 の間」として扱われている（意図は層 4）。
**実測では無害**（層を直した版を作って A/B したところ、fertilize 回数・イチゴ収量・
資金のいずれも動かなかった）。掃除の世代で直す。
