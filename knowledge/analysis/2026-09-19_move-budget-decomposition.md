## 6. 学び（ゲーム構造への還元）

1. **移動は「距離」ではなく「予算」で決まる。** エンジンは 1 unit-hour = 1 行動、1 日 = 24 時間、
   日跨ぎで farmer はスポーンへ戻り hands は破棄される（`kaggriculture.py` 879-881）。
   したがって**移動の価値は「その日のうちに 1 手打てたか」で 0 か 1 かに切り替わる**。
   距離の最適化（迂回 207 h）より、**到達可能性の判定（無駄足 533 h）の方が 2.5 倍大きい。**
2. **空きタイルは二重に損をする。** 生産を失うだけでなく、「隣に仕事が無い」状態を作って移動量を増やす。
   相手の hop/work が d11 以降 0.55-0.80 に下がり我々が 1.2-1.65 に上がるのは、
   盤面密度そのものが移動コストの関数だから。**tile_util は目的ではないが、労働効率の入力ではある。**
3. **ゾーン所有は「距離の節約」と「労働の保存」のトレードオフで、今は前者に振り切れている。**
   ゾーン化（gen0022）は移動を減らすために入れたが、その副作用で**遊んでいるユニットが仕事を取れない**。
   d11-d20 の PASS の近傍にあった仕事の 49% は同じ日に別のユニットが実行しており、
   **仕事量が足りないのではなく、割り振りが固定されている。**
4. **farmer は「遊撃」という役割設計そのものが赤字**。ゾーンを持たない＝所有権の網の外に置かれる、が
   `_owner_can_come` の設計では「取れない」と同義になる。**719 unit-hour の 60% が PASS。**

## 7. 次の世代への実装案（2 つだけ。どちらも IDEA_POLICY §出してよい 4「労働割当の構造変更」）

### 案 A: 労働の保存則 — 遊ぶくらいなら他人のゾーンの仕事を取る

`_owner_can_come` の解除条件を「**所有者が今日まだ来られるか**（距離 + 1 ≤ 残り時間）」から
「**所有者のバックログが残り時間を超えているか**」に変える。所有者が自ゾーンに抱えている todo 数が
残り時間より多ければ、その todo は今日どうせ落ちるので他のユニットが取れる。
併せて **farmer をゾーン割当の一員にする**（`n_zones = n_hands + 1`）。シェッド遊撃は
「シェッドに実在する仕事がある時だけ」の例外に格下げする。

- 対象量: PASS 1,299 h（farmer 431 + hands 868）。d11-d20 では 330 h。
- 根拠: §5（PASS の 96-100% で空いた仕事が 3 歩以内、45% は足元）と §3（farmer の 60% PASS）。
- **定数の微調整ではない**: 残り時間との比較は 24 時間 / 日というエンジン規則から出る量で、
  調整可能な閾値を新設しない。

### 案 B: 到達可能性ゲート — 今日中に着けない todo を選ばない

ユニット割当の key に「`距離 + 1 ≤ 23 − hour`」のフィルタを入れ、これを満たす todo が無ければ
**満たす todo の中から選び直す**（無ければ PASS）。

- 対象量: END_OF_DAY 375-500 h。そのうち **259-367 h は、歩き出した時点で到達可能な代替が実在した**（§2）。
  h23 の MOVE 147-185 h は定義上全損なので必ず消える。
- 根拠: エンジンの daily reset 規則（`kaggriculture.py` 879-881）。
- 案 A と独立に効くが、**A で生まれた「取れる仕事」を B が今日中に片付く方へ向ける**ので相乗する。

### 却下した小手先案

- `FALLBACK_CYCLE_DAYS` 5 → 3（carrot 予約を早く解く）/ IDEA_POLICY 禁止 1（閾値の ±微調整）。
  **加えて実測でも否定**（§5 末尾。d19-24 の空きに carrot 予約地は 0 枚）。
- `LAST_PLANT_HOUR` を 20 → 22 に延ばす / 禁止 1。h21-23 の PASS は 341 件あるが、
  当日の水やりが間に合わない植付は確定枯れなので、締切自体は規則から出ている。
- hands を増やして PASS を埋める / 禁止 2（hands ±1）。そもそも我々の方が総 unit-hour で +491 多い。
- FERTILIZE の運搬ゾーン例外の拡張 / 禁止 1。総量 171 h で主因ではない。

## 8. 測定器への提案（人の判断が要る）

`control/targets.json` の `micro` に **`move_per_work`（生産行動あたりの MOVE hour）** を入れると、
