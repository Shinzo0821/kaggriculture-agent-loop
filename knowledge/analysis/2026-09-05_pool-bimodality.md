## なぜ rating が動かないか

`pool.rating` は相手の固定レーティングに対する Bradley-Terry の当てはめ。
勝率が 550（gen0018）以下に全勝・836.7（rayk_c95）以上に全敗なら、
**最尤解は 550 と 836.7 の間のどこかに決まり、その区間の中では尤度がほぼ平ら**。
gen0022 → gen0024 の `rating_delta +6.2` の中身は 1,100 戦のうち **3 勝**（297 → 300）で、
符号が数試合で決まる。24 シードでは 3 勝の差すら出ず、rating は完全に一致した。

## 中間帯を作れるか

必要なのは「gen0024（$47-58k）と強帯（$114-120k）の間、$70-100k を出す相手」。

- **公開実装**: `agents/sparring/` の 9 体は starter($3.6k) / georgy($7.7k) の次がいきなり
  強帯 $114-120k。間が空いている（`yhay81_router` は macOS arm64 専用で既定無効・未レーティング）。
- **自系統**: 上の表のとおり gen0003〜gen0022 まで全部 $28-58k で、こちらが全勝する側。
- **残る手は人工的に作ること**（強帯の実装を手加減した変種を作る等）。これは
  「外の数字」ではなくこちらの構成物になるので、**指標の自己参照**に近づく。採用は保留。

→ **中間帯は現時点で作れない。** プールの構成は変えず、ゲート側を直した。

## 追記（同日）: `strong_opp_money_mean` の帯は「プール劣化」の検知に使えない

`control/targets.json` の `strong_band_money`（$106-115k）は「`pool.strong_opp_money_mean` が
この帯に入っているかでプールが劣化していないか確認できる」と書いてある。しかし**市場は共有**で、
相手の資金はこちらのエージェント次第で動く（`harness/evaluate.py` は候補と相手を同じ試合に入れる）。

実測（24 シード、強帯 8 体の資金平均）:

| 候補 | strong_opp_money_mean |
| --- | --- |
| gen0025 | $112.4k |
| gen0026（労働の 4 点のみ。市場破壊あり） | **$102.6k** |
| gen0026（出荷制御を直した採用版） | **$105.9k** |

→ **この帯は「プールが劣化した」と「候補が強くなった／市場を潰した」を区別できない。**
gen0026 の $105.9k は前者ではなく後者。帯から外れたこと自体は警報として正しく働いた
（`too_good` と後半 slope の負と合わせて 3 つ同時に鳴り、市場破壊を見つけられた）が、
**「帯に戻すこと」を目標にしてはいけない**（相手を儲けさせるのが目標になってしまう）。
プール劣化の検知には、候補と無関係な量——例えば**強帯どうしを対戦させた時の資金**——を使うべき。
`harness/rate_pool.py` は総当たりを回しているので、そこから取れる。次にプールを触る時に直す。
