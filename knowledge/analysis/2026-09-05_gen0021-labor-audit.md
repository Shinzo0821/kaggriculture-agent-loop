# 2026-09-05 gen0021 労働監査: 拡張が負けるのは「移動76%・CARE0%」の割当実装のせい

対象: seed42 gen0021 vs gen0018（$29.8k vs $48.4k）。リプレイのアクションを hand-hour 単位で日次集計
（スクリプト: `harness/audit_replay.py`、`run_match.py --replay` の出力を食う）。

## 実測（gen0021, 12hands 期 = d11-d28）

| 指標 | 値 |
| --- | --- |
| 総 hand-hours/日 | 288（12hands × 24h） |
| MOVE | **216-232（約76%）** |
| FEED | 3-12（12頭に対し） |
| CARE | 0-4 → **uncared 10-12頭/日（d7-d25 ほぼ毎日）** |
| WATER/HARVEST/PLANT | 合計 20-30 |
| unfed@EOD | d13:3 d15:9 d17:12 d20:9 d22:9（隔日パターン） |
| 飼料小麦在庫 | 常時 12-24（**在庫は枯れていない**） |

対照 gen0018（6頭・8hands・1クアドラント）: unfed=0 が d1-d28 全日、$1.3-1.9k/日 の安定成長。

## 原因（コード構造、agents/gen0021/main.py）

1. **毎時グローバル最近傍再割当**（L317-371）: 全ユニットが毎時 (優先度, 距離) で todo を選び直す。
   2クアドラント（10x10 グリッド）では通勤 5-10 タイルが常態化し、hand-hour の 3/4 が移動に消える。
   割当に持続性がないので「向かっている途中に別の todo に釣られる」振動も起きる。
2. **CARE 優先度 3.5 は実質デッドレター**（L246）: WATER 2.90-3.05・HARVEST 1.9-2.2・PLANT 2.x より低く、
   労働が飽和している間は永遠に順番が来ない。gen0018 の羊毛経済は「CARE 6日分バンク→高値日に収穫」
   が原資（本ファイル L17 のコメント参照）なのに、12頭に増やした途端 CARE が全滅して yield ボーナス
   （pending_care_bonus=4 が付いたまま）を捨て続けている。
3. **FEED は在庫でなく物流の問題**: FEED todo は「小麦を持つ hand」しか取れず（L333）、
   PICKUP は「2個持ってたらスキップ」（L348）。12頭を養うには hands がシェッド往復を繰り返すしかなく、
   その往復も MOVE に計上される。隔日 unfed スパイクはこの物流の脈動。

## 結論（EXP0021 の分岐への答え）

**拡張が経済的に不利なのではなく、割当実装が拡張に追随できていない。** 上位が 3 クアドラント・14-18頭を
12hands で回せている以上、2 クアドラント・12頭は余裕のはず。gen0022 の設計指針:

1. **ゾーン固定割当**: 農場を隣接タイル集合（クアドラント単位）に分割し、hand は自ゾーン専属。
   日次ルーチンは FEED→CARE→WATER→HARVEST の固定順。ゾーン内移動は 2-4 タイルで済む。
2. **小麦物流の一括化**: ゾーン内の動物数ぶんの小麦を朝1回のシェッド訪問で積む（PICKUP qty=動物数）。
3. **CARE を FEED 直後の優先度に**: 全頭毎日 CARE（バンクは HARVEST 時に清算される）。
4. 成功判定は監査で機械化: `audit_replay.py` で unfed=0・uncared=0（d1-d28）を確認してから評価に回す。
