# 「同じタイルを何度も訪ね直す」の根本原因 — 層で農場を一巡する構造

- 日付: 2026-09-06 ／ 対象: gen0031（王者）／ 出所: 人の指摘（「水やりをいろんなマスにした後に
  一つ一つ収穫してるのが二度手間」）を実測で確認したもの
- 関連: `2026-09-05_micro-audit-gen0022.md`（利用率・収量）、`2026-09-05_gen0021-labor-audit.md`（移動の浪費）

## 2. 機構（なぜそうなるか）

ユニットの行動選択は `main.py` の `eval_todos` 1 箇所に集約されている。キーは

```python
key = (pri_layer(eff), d, eff)     # 層 → 距離 → 優先度 の辞書式
```

`pri_layer` は**仕事の種類だけ**で決まる（`LAYER_BOUNDS`）。距離はその下位キーでしかない。したがって:

> **同じタイルに層の違う仕事が 2 つあると、その間に必ず農場のどこかへ歩き出す。**
> 層 L の仕事が農場のどこかに 1 つでも残っていれば、距離 0 にある層 L+1 の仕事より必ず先に選ばれるため。

結果として 1 日の労働は「層ごとにゾーンを一巡する」形になる。層は 7 つあるので最大 7 周。
動物タイルは FEED(層1) / CARE(層1) / HARVEST(層2) / COLLECT_FERTILIZER(層6) の 4 つが別々の層に
散っているので、必ず 3 周ぶんの往復が発生する。gen0022 の `zone_labor` が
「ルーチンは FEED→CARE→WATER→HARVEST の固定順」と書いているのはこの周回のことで、
**設計どおりの挙動であって、設計そのものが無駄を生んでいた。**

## 3. なぜ 31 世代かかったか（プロセス側の原因）

1. **表現が「その場で終わらせる」を書けない。** 優先度は todo 1 つに 1 つの
   スカラーで、しかも全ユニット共通の全順序。「誰がどこに立っているか」は
   キーの下位でしか効かない。gen0026 の `pri_layer` は距離を層の中でだけ効かせる
   部分的な手当てだったが、層の境界を**仕事の種類**で引いたので、同じタイルの
   2 つの仕事が別の層になることは構造として残った。
2. **同じ改善を 1 度試して、優先度の入れ替えとして棄却している。** EXP0024 は
   「WATER を HARVEST の後ろに置いて同じ訪問で終わらせる」を A/B し、小麦収量
   3.82→3.69・メロン 6.00→5.39 で棄却した。これは正しい判定だが、**測ったのは
   「全体の優先度表を書き換えた版」**であって「その場で終わらせる」ではない。
   優先度表の入れ替えは、どの株に水がやられるかまで変えてしまう。
   → 直すべきは優先度表ではなく**選択キー**（立っているユニットにだけ効く項）。
3. **指標が捉えていなかった。** `audit_replay.py` は unfed/uncared/move%、
   `micro_audit.py` は利用率・収量・3 歩以上%。move% は「必要な移動」と
   「往復のやり直し」を区別しない。歩数ヒストグラムの 0 の段（＝その場で継続）は
   ずっと印字されていたが、`--assert` の基準になっていなかったので誰も見なかった。
4. **昇格の物差し（資金マージン）にミクロ改善への分解能が無い。** gen0032 を測って
   確かめた: マージン差の点推定は **24 シードで +$583、50 シードで −$986 と符号が入れ替わる**
   （CI はどちらも 0 をまたぐ）。一方「自分の最終資金」は両方で正（+$1,911 / +$1,207）。
   理由は町の抽選が**両農場の**空きタイル数に依存すること
   （`2026-09-06_town-draw-depends-on-empty-tiles.md`）で、自分の産出が増えると
   相手の資金も一緒に上がる（24 シードで +$1,328）。
   seed 1019 vs boatlee_v16 では自分 $53.1k→$68.0k（+28%）なのに相手も $102.9k→$133.7k で、
   マージンは −$13.9k。**ミクロの前進は、この物差しでは構造的に見えない。**
   → ミクロ指標に基準を置く（`micro_audit --assert`）以外に守る手段が無い。

## 4. 対応

- **gen0032**: `eval_todos` のキーに訪問完了を入れた（`DAILY_TILE_OPS` / `VISIT_LAYER`）。
  優先度表は 1 つも触っていない。→ `knowledge/experiments/EXP0032_visit-completion.md`
- **指標**: `micro_audit.py` に `inplace_share`（その場で続けた畑仕事の割合）と
  `tile_revisit_share`（同じ日に同じタイルへ訪問し直した回数）を追加し、
  `control/targets.json` の `micro` に強帯 8 体の実測から基準を置いた。
- **結果**: ミクロは全部改善したが、**資金は 50 シードでも検出不能**（EXP0032）。
  浮いた約 750 unit-hour を吸う仕事が農場に無い（`tile_util` 0.752→0.738、strong_slope −111）。
  gen0029-0031 の「制約は出口（市場の吸収量）」と整合する。**出口を広げてから再測定する。**
- **今後の型**: 「ユニットの位置に依存する価値」は優先度表では書けない。
  同種の穴（例: 通り道にある ripe な株を素通りする — seed42 d15 h16 で実測）は
  キー側で直す。優先度の数値をいじる案は `IDEA_POLICY` の禁止側でもある。
