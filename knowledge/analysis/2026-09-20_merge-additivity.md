**結論を 3 行で。** (1) gen0058 / gen0060 / gen0062 の 3 機構の合流は、マージンで
**有意な非加算性が検出されなかった**（交互作用 **+654.7 [−494.2, +1,803.5]** 全プール、
**−57.4 [−1,204.2, +1,089.4]** 強帯）。**「加算だと証明した」ではない**（§6 の限界）。

## 1. 何を測ったか

5 本の既存 eval（`gen0051 / gen0058 / gen0059 / gen0060 / gen0062`）はすべて
**同じプール `e3f96592`・`seed_base 1000`・`steps 720`・50 シード・両席 = 1,300 セル**で走っており、
**セル集合が完全に一致する**（スクリプトが起動時に検査して、崩れたら止まる）。
`games` 配列を `(相手, シード, 側)` で突き合わせ、`evaluate.py::paired_delta` と**同じ推定量**
（セルの重み付き和 → シードごとに平均 → 50 シードで正規 CI、1.96 固定）で線形コントラストを出した。

**検算の範囲**（Codex レビューで訂正した。最初は「3 指標すべて再現」と書いていたが偽）:
- **margin / money の A-D は保存 gate を 0.1 の桁まで再現する** ＝ 推定量の実装検算になっている。
- **slope は違う。** `evaluate.py:332` の `slope_delta` は**丸めた平均の差**で CI を持たない。
  ここの slope は同じセルから**新たに対応付き CI を付けた診断値**（シードあたりのセル数が
  均等なので点推定は一致するが、由来が別。強帯 D は本稿 −100.1 対 gate −100.0 ＝ 丸め差）。
- **F（59 − 58）はどの eval の gate にも無い**（`eval_gen0059.json` の baseline は gen0051）。代数的な検算値。

系譜（各機構は 1 世代 1 機構で分離済み）:

```
gen0051 ──(機構A: 到達可能性ゲート)──> gen0058 ──(機構B: バックログ解除+FIX0030)──> gen0060 ──(機構C: farmer ゾーン参加)──> gen0062
   └──────(機構C: farmer ゾーン参加)──> gen0059
```

**機構 C が 2 つの土台に載っている**（gen0051 の上 = gen0059、gen0060 の上 = gen0062）。
この 1 機構の値を 2 つの土台で比べた差が交互作用 I で、**加算からのずれそのもの**:

`I = (gen0062 − gen0060) − (gen0059 − gen0051) = gen0062 − gen0051 − (A + B + C)`（恒等式）

CI はセル内で 4 世代を合成してから取るので、**独立を仮定した誤差伝播ではなく対応付き**
（Codex の追試: 対応付き se 586.2 対 C・D を独立扱いした se 697.8）。

## 3. c6 の「+$2,361 超加算」はなぜ間違ったか（ここは有意性と無関係に確定）

c6 は「共通 baseline の単機構版の和」として **+3,090.6（B）と +984.0（F = gen0059 − gen0058）** を
足して +4,074.6 とし、実測 +6,435.4（gen0062 − gen0058）と比べて +$2,361 の超加算とした。

**F は farmer ゾーンの単体値ではない。** 対応付き推定量は telescope するので

`F = (gen0059 − gen0051) − (gen0058 − gen0051) = C − A = 2,690.1 − 1,706.1 = 984.0`

＝ **「farmer ゾーン − 到達可能性ゲート」という 2 機構の差**である。これを単体値として足すと
**ゲートぶん（A = +1,706.1）が二重に引かれ**、差額 +$1,706 がそのまま偽の超加算になる。
残る +$655 が本物の交互作用で、**1,706.1 + 654.7 = 2,360.8** と c6 の +2,361 にちょうど一致する
（セル単位でも `F = C − A` と `I = E − (A+B+C)` は浮動小数誤差 1.8e-12 以下で成立）。

→ **規則: 機構の単体値が欲しいときは、gate 要約の引き算をしない。共通の土台に対するセル単位の
コントラストを取る。** 「数えたつもりの量が別の量」（HANDOFF の型 iii）の 4 例目。

1. **この C × 土台の組合せでは、合流の確認だけを目的とした追加 eval の優先度を下げてよい。**
   マージンの非加算性は ±$1.8k 以内に収まっており、設計段階では「測った機構の和」を出発点にしてよい
   （合流世代の eval 1 本 15 分は「加算の確認」ではなく**新しい土台のベースライン取得**として払う）。
   **1 組しか観測していないので、一般則としては外挿しない。**
2. **次に価値がある測定は slope 側**（§4 の仮説）。`gen0063`（トマト = 売上側）とは別系統。
3. **この手口（保存済みセルの線形コントラスト）は新規 eval 0 本で交互作用を出せる。**
   1 機構が 2 つの土台に載っている系譜がほかにもあれば同じ検算ができる。

## 6. 限界（読む人への注意）

- **非有意は加算性の証明ではない。** 事前に「これ以下なら加算とみなす」同等性の幅を決めていない。
- **多重比較の調整をしていない。** margin / money / slope × 全プール / 強帯 × 7 コントラストを見ている。
- **正規近似・1.96 固定。** 50 個のシード平均の分布や外れ値は点検していない（`paired_delta` と同じ仕様）。
- **farmer ゾーンの 2 実装はバイト同一ではない。** gen0059（親 gen0051）と gen0062（親 gen0060）は
  中核（`unit_zid` による farmer の区画所有、`farmer_shed` の 3 段 `crit`）が同一だが、gen0062 側は
  gen0060 のバックログ基準 `_owner_can_come` と噛み合わせるぶん差分が大きい（hunk 11 対 15）。
  I は「同一機構の土台依存」ではなく「**土台に適応させた実装を含む世代差**」のコントラストである。
- 各世代が「記載された機構以外を含まない」ことはここでは検証していない（meta.json の `mechanisms` 台帳依拠）。
- すべて `seed_base 1000` の同一シード帯・この相手プールへの条件付き結果。LB や別プールへ直接一般化できない。
  **別帯での再現は `records/eval_gen0062_sb2000.json`（c7 でキュー投入済み）待ち。**
- 3 機構は同じ「労働割当」の系統なので、**分野が離れた機構（売上側 × 労働側）には外挿できない。**
  `gen0063`（トマト）が pass したときの合流は改めて測る必要がある。
