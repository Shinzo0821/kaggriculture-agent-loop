# 2026-09-05 相手の稼ぎを削るのは有効な手段である（枠組みの訂正）

- きっかけ: gen0026 の評価で「資金の伸びの正体は生産ではなく市場破壊だった」と書いたところ、
  ユーザーから「相手の稼ぎを削るのは悪いことなのか。削れるだけ削り、自分は増やせるだけ増やして、
  結果として相手より多く持つのがこのゲームの目標ではないのか」と指摘を受けた。**指摘が正しい。**
- さらに「勝敗が飽和した相手への削りを前進と数えるな」と書いたが、**これも誤り**だった
  （下の「なぜ誤った規則を書いたか」）。実際は逆で、**ゲートは削りを構造的に過小評価している。**

## 事実: ゲートは自分の資金しか見ていない

`harness/evaluate.py` の `paired_delta` は `g["cand_final"] - b["cand_final"]`。
**相手の資金は 1 バイトも入っていない。** したがって:

- 生産で自分の資金が $9k 増える変更 → ゲートは **+$9k** と評価する。
- 相手の資金を $9k 削るが自分は横ばいの変更 → ゲートは **$0** と評価し、**却下する**。

勝敗は `cand_final > opp_final`（`harness/run_match.py`）で決まるので、
**勝ちに効くのはマージン（自分 − 相手）**。ゲートはその片側しか見ていない。

## 実測（gen0026 vs gen0025、50 シード）

| | 全プール（1,100 戦） | 強帯のみ（800 戦） |
| --- | --- | --- |
| 自分の資金の差 ← **ゲートが見ている値** | +$8,974 [CI +6,152, +11,796] | +$7,588 [CI +4,007, +11,169] |
| 相手の資金の差 ← ゲートは見ていない | −$5,095 [CI −9,076, −1,115] | −$6,954 [CI −12,412, −1,497] |
| **マージンの差（勝敗を決める量）** | **+$14,069 [CI +11,820, +16,319]** | **+$14,542 [CI +11,441, +17,643]** |
| 勝敗の反転（敗→勝 / 勝→敗） | 0 / 0 | 0 / 0 |

- gen0026 は**ゲートが言うより 1.6-1.9 倍良い**。
- **マージンの方が CI が狭い**（$4,499 vs $5,644）。同一シードのノイズが両者に共通に乗るので、
  差を取ると打ち消える。統計的にもマージンの方が良い推定量。

## なぜ誤った規則を書いたか（2 つの誤りが重なった）

1. **ゲートが何を測っているか読み違えた。** 「自分 +$8,974 / 相手 −$6,954」を観測して、
   ゲートの +$8,974 に相手の削りが混ざっていると考えた。混ざっていない。
2. **「生産は本物・削りは不純」という検証していない前提を先に置き、後から理屈を作った。**
   その理屈（「勝敗を反転させないから」）は**生産にも同じだけ当てはまる**: 強帯戦で自分の資金が
   +$7,588 増えても反転した試合は 0 戦（上表）。削り固有の問題ではなく、
   既に記録済みの「プールが飽和している」問題（`2026-09-05_pool-bimodality.md`）そのものだった。

→ **「勝敗が飽和した相手への削りを前進と数えるな」は撤回する。** 飽和の問題は削りとも生産とも無関係で、
   プールの構成の問題。削りは生産と同じだけ勝ちに効く。

## 残る（本物の）注意点

**自分の絶対額が下がる型は避ける。** gen0026 の «労働 1-4 のみ» 版は、相手をより大きく削ったが
自分の資金も s7 で $73k → $36k に落ちた。マージンでは勝ちだが、
- 自分の資金が薄いと再投資（土地・動物・種）が回らず、翌日以降の生産能力そのものが落ちる。
- 終盤の清算余力が減り、価格の当たり外れに対する頑健性が下がる。
出荷制御を直したのは**この理由**であって「市場を潰すのが悪いから」ではない。

## 運用への反映

- **削りを理由に世代を却下しない。** 却下の理由になるのは「自分の絶対額が下がる」型だけ。
- **提案: 昇格ゲートの `money_delta_paired` をマージン（`cand_final − opp_final`）に変える。**
  勝敗の定義と一致し、CI も狭い。今日までの昇格判断（gen0024/0025/0026）はどれも
  マージンの方が大きいので、遡って結論は変わらない。**人の判断待ち。**
- `gate.too_good` の閾値（資金差平均 > $8,000）はマージンに変えるなら基準も見直しが要る。
- **本当に欲しい指標は「勝敗の反転数」**。現プールでは 0/0 で動かない（強帯 0% / 弱帯 100%）。
  こちらが強帯に届き始めれば自然に測れるようになる（`2026-09-05_pool-bimodality.md`）。
