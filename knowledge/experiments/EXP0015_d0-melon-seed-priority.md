# EXP0015: d0 メロン種の一括確保（種律速の解消を狙う）
- 日付: 2026-09-04 ／ 世代: gen0015（親: gen0013 現行王者）
- 仮説: cycle2 のリプレイ解剖でメロンスプリントが設計7タイルに対し**実測3タイルで頭打ち**、d4 時点 seeds MELON:1・粗利 +$4.4k（設計 $7.5k の半分以下）と判明。gen0013 の自主キャップ `min(..., 4)` が第1波の種入手を律速していると見た。README §Market に BUY_SEED の数量上限は無い（`maxMarketOrdersPerTurn=10` は"注文数"の上限で数量ではない）。d0 は COW購入後 money=2600 で `affordable=(2600-2000)//80=7` と7個買える現金がありながらキャップ4で頭打ち＝**現金でなくキャップが律速**。キャップをタイル数7へ上げれば d0 に第1波7種を一括購入し、以後は hands7 の労働だけが植付律速になる（EXP0013 の意図した状態）。設計粗利 $7.5k が出れば gen0013 を絶対資金で上回るはず。

- 学び（重要）:
  1. **cycle2 が「種律速(seeds:1@d4)」と見た現象の真因は労働律速だった。** seed-42 リプレイで gen0015 のメロンは d10 に ~$5.7k を実際に売却できている（money 471→6191）＝メロン粗利は設計どおり出た。にもかかわらず**最終資金は gen0013 より低い** → 早期に7タイルを一斉に植えると**7株ぶんの水やり負荷が hands 増員前に先行**し、労働が中核動物の CARE/給餌/収穫/水やりから引き剥がされて中核出力が落ちる。gen0013 の `min(4)` キャップは**種購入を労働ランプに合わせて自然にスタガリング**していた副次効果があり、それが最適だった。
  2. **EXP0004 の「同時投入のキャッシュ/労働枯れ」失敗モードの再確認。** メロンは順序（staggered）が本質で、原資も労働も一斉投入すると中核を壊す。gen0013 は既にこの順序が最適近。
  3. **メロン資本スプリント系統は gen0013（staggered 4/turn + hands7）で頂点に達した。** cycle2 の gen0014（売却ペーシング, Track A）棄却と本 gen0015（種前倒し, Track B）棄却で、スプリントの前後（種入手側・売却側）双方を押しても改善しないことが確定。**次はスプリント内部の微調整でなく、別レバー（需要適応イチゴ+労働 / 増員先の使い方）へ移る。**
- メタ: §7 3世代ルールには非該当（melon-sprint 系統は gen0012 中立→gen0013 昇格→gen0015 棄却で、直近が昇格なので連続改善なしではない）。ただし「スプリントを直接強化する変数」は打ち切り、Track B は需要適応イチゴへ切り替える。
