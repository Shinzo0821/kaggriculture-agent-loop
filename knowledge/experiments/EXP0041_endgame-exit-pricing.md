# EXP0041: 終盤出口の価格最適化（生きた出口イチゴの叩き売り停止）＋ FIX0003 / FIX0011

- 日付: 2026-09-06 ／ 世代: gen0041（親: gen0036＝現王者）
- 仮説: 生きた出口（イチゴ）を終盤に $1 へ全量ダンプしているのを、価格モデルから解いた
  「床を割らない売却ペース」に置き換えれば、削らずに換金額が増える。
  出所は `knowledge/IDEA_POLICY.md` の「未使用の観測の利用／ローカルと LB のズレを消す」側
  ＋ 738619#11（現 8 位「売却タイミングを ML で最適化」＝出口が上位の差別化要因）。
- 変更:
  - **CHANGE1（Track A core）**: SELL_FLOORS ループの終盤オーバーライド分岐
    （`day >= DUMP_DAY or shed_pressure >= SHED_DUMP` で `qty = n`）を、`LIVING_EXITS=("STRAWBERRY",)`
    かつ `day < FINAL_DAY` の時だけ価格床ペース配分に置換。過剰側の線形価格
    `price = base − GLUT_AMP·(inv − I0)`（STRAWBERRY: amp = 1.6·120/100 = 1.92、README 価格表から導出）
    から `glut_headroom`（その floor を割らない売却数）を解き、floor を `days_left/ENDGAME_RAMP_DAYS`
    で base→$1 に線形に下げ、`clearance = ceil(n/(days_left+1))` と max を取って FINAL_DAY までに
    確実に吐き切る。牛乳・肥料の denial ダンプ／最終日全量／メロン(ALWAYS_SELL)・羊毛は不変。
  - **CHANGE2（FIX0003, major）**: 最終日は手持ち在庫 `carried_item` を各 SELL 数量に上乗せ。
    DROP(step2)→SELL(step3) が同一ターン内で shed に載り、過剰売却は在庫尽きでエンジンが安全停止
    （`kaggriculture.py:652`）するので純粋な会計修正。4 世代連続 open だった清算漏れを解消。
  - **CHANGE3（FIX0011, minor）**: 最終行動ターン（d29 h22, step 718）の COLLECT_FERTILIZER を抑制。

- 学び（確定）:
  1. **イチゴの床保護はほぼ空振り**。cycle3 Analyst（`knowledge/analysis/2026-09-06_top-endgame-sell-rates.md`）
     の予測どおり、**イチゴは需要律速で終盤も床に落ちない**（良店舗構成では sink≥25/日・価格 $150-220 維持）。
     叩き売りの前提だった「イチゴ d25-29 に 81 個を $7-54」は特定シード・特定店舗構成の産物で、50 シード
     平均では発現しない。**価格式が既知でも、そもそも過剰在庫にならない品目に床ペースを入れても効かない。**
  2. この世代の +$33 マージンは **FIX0003（最終日 DROP→SELL 反映・4 世代連続 open）と FIX0011** の
     終盤清算由来と推定（CHANGE1 は多くのシードで発火しない）。これらの fix は gen0042 に移植済みなので
     gen0043 でも保持される。
  3. **効くのは「イチゴをもっと作る」側**＝生産量（動物・タイル利用率）。敗因解剖
     （`knowledge/analysis/2026-09-06_loss-vs-extremely-sus.md`）が示す構造ギャップ（利用率 68%→93%・
     動物 12→17）を埋める世代へ計画を寄せる（cycle4 で Strategist を起動＝下記レビュー記録）。
  4. 牛乳/肥料 dump を残したのは正当（denial は相手の資金を削る・gen0037 の実測）。この判断は不変。
