# CLOSED — 閉じた系統の台帳

- 作成: 2026-09-05（ワークフレーム改善 P0、ワークフレーム改善プラン（公開版では除外） §2-C）

**目的**: 「もう試した」を根拠付きで記録し、同じ案を繰り返さない。ただし
**閉鎖はその時の指標での閉鎖**であって永久ではない。指標が変わったら
`再検討` 欄が `対象` の系統は自動的に再検討の候補に戻る。

## 読み方（列の意味）

| 列 | 意味 |
| --- | --- |
| 指標 | 閉じた時に使っていたゲート。`H2H(旧)` = 自系統+starter の勝率（v0.4 以前）／`pool(v0.5)` = 相手プール・レーティング + 対応付き資金 CI |
| シード | 判定に使ったシード数（片側。両側で 2 倍の試合数） |
| CI | 勝率の Wilson95 か、資金差の 95%CI。**当時 CI を残していない場合は `—`** |
| 再検討 | `対象` = 旧指標での棄却なので v0.5 で再実験してよい／`確定` = 指標を変えても結論が変わらない |

## 重要な注意（2026-09-04 の方針転換で判明したこと）

上表の `H2H(旧)` はすべて **自系統 + starter だけの相手**で測っている。
この相手構成では市場が 2 人で共有されるため、**拡張型（土地を買って後半に伸びる型）が
ミラー戦で glut を起こして自滅する**。LB 上位が実際に使っている型を一度も再現しない。
`再検討: 対象` の行は、この構造的バイアスの犠牲であって、
「その戦略が弱い」ことの証拠ではない。

- 詳細: `state/STATUS.md`「何が起きていたか」／`REQUIREMENTS.md` v0.5 更新履歴。
- 実際に gen0022（拡張 2 クアドラント）は v0.5 の新指標で昇格し、LB も 559 → 614.1 に上がった。

## 追記のしかた

系統を閉じたら**その場で 1 行足す**（EXP を書く時に一緒に）。
- 「指標／シード／CI」の 3 つを空欄にしない。書けないなら `—` を入れ、再検討を `対象` にする。
- 指標（ゲート・相手プール）を変えたら、`再検討: 対象` の行を STATUS の「次の一手」候補に戻す。
