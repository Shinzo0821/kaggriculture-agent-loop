# EXP0032: 訪問完了 — 立っているタイルの仕事を、歩き出す前に終わらせる

- 日付: 2026-09-06 ／ 世代: gen0032（親: gen0031）
- 出所: **人の指摘**「収穫時に水やりをいろんなマスにした後に一つ一つ収穫してるのが二度手間。
  水やり＋収穫→移動→水やり＋収穫にすればいい」。根本原因の分析は
  `knowledge/analysis/2026-09-06_layer-sweep-root-cause.md`。
- 仮説: `IDEA_POLICY` §出してよい 4（労働割当の構造変更＝割当アルゴリズムそのもの）。

## 仮説

ユニットの選択キーは `key = (pri_layer(eff), d, eff)` の辞書式で、**第 1 キーの層は
仕事の種類だけで決まる**（`LAYER_BOUNDS`）。距離はその下位。したがって

> 同じタイルに層の違う仕事が 2 つあると、農場のどこかに上位層の仕事が 1 つでも残っている限り、
> **必ずその 2 つの間に歩き出す。**

1 日の労働は「層ごとにゾーンを一巡する」形（層は 7 つ）になる。動物タイルは
FEED(層1) / CARE(層1) / HARVEST(層2) / COLLECT_FERTILIZER(層6) が別々の層なので構造的に 3 訪問。

日課のタイル仕事は (a) 毎日リセットされ (b) 場所が動かず (c) いつやっても 1 手なので、
後回しにしても得るものが無く、2×距離 の往復だけが増える。立っているタイルのそれらを
層 1（緊急給餌の直下）に上げれば往復が消える。

## 変更

`eval_todos` のキーだけ:

```python
if d == 0 and op[0] in DAILY_TILE_OPS:   # FEED/CARE/WATER/HARVEST/COLLECT_FERTILIZER/FERTILIZE
    lay = VISIT_LAYER                     # = 1
else:
    lay = pri_layer(eff)
key = (lay, d, eff)
```

**優先度表（`LAYER_BOUNDS` と各 todo の pri）は 1 つも変えていない。** タイルの中の順序は
`eff` がそのまま決めるので FEED→CARE→HARVEST→COLLECT_FERTILIZER の順は保たれる。
層 0（consecutive_unfed≥1 の緊急給餌）には上げない＝家畜の死だけは他所へ歩かせる。
PLANT/DIG/BUILD/PLACE/物流は対象外（盤面の形を変えるので (a)(b) が成り立たない）。

測定器側: `harness/micro_audit.py` に `inplace_share` と `tile_revisit_share` を追加し、
`control/targets.json` の `micro` に強帯 8 体の実測から基準を置いた。
