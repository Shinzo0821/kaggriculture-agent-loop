# EXP0061: 到達可能性ゲートの 3 つの穴（最終日 carve-out / 最終日の肥料回収 / 一括 PICKUP の迂回）

- 日付: 2026-09-19 ／ 世代: gen0061（親: gen0058）
- 仮説: 王者 gen0058 の到達可能性ゲートは「歩き出しても今日は実行できない行動を選ばない」という規則
  だが、**予算式が場所によって違う**ので 3 つの穴が残っている（すべて gen0058/gen0059 の昇格前
  Codex レビュー由来。IDEA_POLICY の「出してよい」= 労働割当の構造変更 / ローカルと実機のズレを消す変更）。
  - **FIX0029**: ゲートの `day < FINAL_DAY` carve-out が終端規則と逆向き。最終日は「届かなくても運ぶ」
    日ではなく、位置も在庫も持ち越せないので**届かない移動の価値は通常日以上にゼロ**。しかも最終行動
    ターンは h22（`LAST_ACTION_HOUR`）。
  - **FIX0028**: FIX0011 の COLLECT_FERTILIZER 抑制が h22 以降しか見ておらず、h21 に遠いタイルで
    回収すると帰りの DROP の手番が無い（肥料 1 個が死蔵）。
  - **FIX0031**: ZWHEAT / ZFERT の一括 PICKUP は `eval_todos` の**外**で `best_key` と比較されるので
    ゲートを丸ごと迂回する。gen0058 の実測では真の h23 残存 MOVE 7/6/10 のうち **6/6/9 がシェッド方向**。
- 変更（新規定数 0 件。既存の式の適用範囲だけを直した）:
  1. `action_hours_left(day, hour)` を新設し、**ゲート本体 / `_owner_can_come`（所有者の保護）/
     FEED・CARE の最寄り判定 `dmin`** の 3 箇所が同じ予算値を共有するようにした。通常日は gen0058 と
     厳密に同値、最終日だけ h22 で切る。3 箇所を同時に狭めるのは、gen0058 が塞いだ「誰も来ない穴」
     （保護の対象集合と最寄り判定の対象集合のズレ）を最終日に再発させないため。
  2. 最終日の COLLECT_FERTILIZER を `hour >= LAST_ACTION_HOUR - shed_d` で抑制（shed_d=0 で FIX0011 と一致）。
  3. ZWHEAT / ZFERT に `d + 1 <= hours_left` を課す。落ちたら従来どおり全体 fallback へ回る。

### (a) FIX0028 + FIX0029 だけの版は、資金に 1 ドルも効かない（3/3 シードで完全同値）

FIX0031 を入れる前の gen0061 と親 gen0058 を同一シードで走らせ、**719 ターン分の行動列を突き合わせた**。

| seed | 行動が違うターン | 最初の差分 | 最終資金（候補 / 親） |
| --- | --- | --- | --- |
| 7 | 5 | d29 h19 | 75,179 / 75,179 |
| 42 | 3 | d29 h21 | 60,437 / 60,437 |
| 123 | 5 | d29 h19 | 69,754 / 69,754 |

差分の中身は**すべて「futile な MOVE → PASS」**（seed 7: `WEST/EAST/NORTH` 計 8 手と
`COLLECT_FERTILIZER` 1 手が PASS になった）。**空いた unit-hour は 1 つも生産行動に変換されていない。**
最終日 h19 以降には、そのユニットが今日中に着いて実行できる代替の仕事が**盤上に 1 件も無い**からで、
これは構造的な帰結（収穫も売却もその時点で終わっている）。

→ **FIX0028 / FIX0029 は「正しさの修正」であって「前進」ではない。** 効果量は小さいのではなく**ゼロ**。
   台帳の `why`（「効果量は小さいが確実」）と HANDOFF の「安い前進」は**この点で誤り**だった。

副産物（エンジン仕様の確定）: リプレイ index 719（d29 h23）には両者とも行動が記録されるが、
interpreter 冒頭の `if env.done: return state` で**一度も解釈されない**。DONE は step 718 の処理直後に
立つ（`step >= cfg.episodeSteps - 2`）。**最終の有効行動は d29 h22 ＝ `LAST_ACTION_HOUR` は正しい。**

### (b) FIX0031（一括 PICKUP のゲート適用）だけが全日に効く。スモークでは 3/3 とも負

player0 スロットの有利分を除くため、**`gen0058 vs gen0058` の同一シード（mirror）を対照**に取った。

（`knowledge/analysis/2026-09-05_seed-detection-limit.md`: 方向判断は 24 シード）。50 シード評価の
**主要な確認対象**にする。

考えられる機序（未検証の仮説）は c7 の会計と同じ形: **無駄な行動を消しても価値は生まれず、

## 説明（この分野を知らない人向け 3 行）

- ゲームは 30 日 × 24 時間で、1 時間に 1 マス歩くか 1 つ仕事をするかしかできず、人の位置は毎日リセットされる。
  だから「今日中に着けない仕事」へ歩き出すのは、その時間を丸ごと捨てるのと同じ。王者はこれを弾く仕組み
  （到達可能性ゲート）を持っているが、3 箇所で適用漏れがあった。
- 最終日ぶんの適用漏れ 2 件を直したら、**捨てていた歩行が PASS に変わっただけで、お金は 1 円も動かなかった**。
  最終日の夕方にはもう、代わりにやれる仕事が盤上に残っていないから。
- 3 件目（倉庫へ物を取りに行く歩行にもゲートを効かせる）だけは毎日効くが、3 回の試走ではむしろ負けが増えた。
  無駄を消すと、その人が**別の、もっと悪い仕事**に回ることがある、という今夜 3 回目の同じ形。

## 学び

1. **「安い前進」と見積もっていた修正が、資金ではゼロだった。** しかも 3 シードで偶然ゼロだったのではなく、
   **行動列を突き合わせて「浮いた時間に代替の仕事が存在しない」ことまで確認した**ので構造的にゼロ。
   → 修正台帳の `severity` は**正しさの重大さ**であって**効果量の見積り**ではない。混同していた。
2. **無駄を消しても価値は生まれない、が今夜 3 回目。** c7 は「PASS を消すと 2/3 が通勤 MOVE に化ける」、
   本世代は「futile MOVE を消すと 100% が PASS に化ける」「一括 PICKUP を消すと fallback で悪化しうる」。
   **律速は無駄の量ではなく、浮いた時間の行き先に価値ある仕事があるかどうか。** HANDOFF の
   「次は『PASS → MOVE への化け』自体を減らす方向」は、**その前に「行き先の在庫」を測る**べき。
3. 対照の取り方: 候補 vs 親の 1 戦では **player0 スロットの有利分（seed 7 で +$2,811）** が丸ごと乗る。
   **親 vs 親の mirror を対照に取る**と 1 シードでも差分が読める（対応付き評価の 3 シード版）。
4. **★スモークは符号ごと逆になる**（2026-09-20 追記）。FIX0031 の対応付きスモークは **3/3 とも負**
   （−979 / −757 / −1,310・平均 −$1,015）だったが、50 シードの真値は **+$32.4 ± 70**。
   「3 戦全敗」でも真値は +$32 でありうる。`2026-09-05_seed-detection-limit.md` の規則
   （方向判断に 24 シード）を**符号のレベルで**裏書きした実例。
   **打ち切りにも使ってはいけない**: ここでスモークを根拠に落としていたら「効果量 ≤ +$102」という
   本当に有用な結論（＝この系統にもう測り直す価値が無いこと）は手に入らなかった。
5. **★「検出不能」には 2 種類ある**（2026-09-20 追記）。CI が広くて 0 をまたぐ（＝**測れていない**。
   再測の価値がある）と、**CI が狭くて 0 をまたぐ**（＝**小さいと測れた**。再測の価値が無い）。
   CLOSED.md の `再検討` に入れるべきは前者だけ。**本世代は後者**で、CI 幅を見ずに
   「検出不能だから再検討」と書いていたら、価値ゼロの再実験を将来の夜に 1 本予約するところだった。
